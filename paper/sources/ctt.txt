Executive verdict
The theorem the system needs is reachable, but not literally in every sentence of the briefing. The
repaired result is stronger where it matters and narrower where the stateless protocol cannot carry the
requested meaning.
 1. The keyed seal authenticates an entire broker-issued capsule for one context. It prevents substitution,
    cross-context transplant, and splice construction. It does not prove that the submitted capsule was
    the latest capsule issued to that physical invocation. Earlier capsules are valid bearer objects.
 2. The implemented two-stage seal, which MACs an unkeyed BLAKE3 digest rather than the canonical
    capsule bytes, cannot be reduced to keyed-BLAKE3 PRF security alone. The proof additionally
    needs collision resistance of unkeyed BLAKE3, or a future seal version must MAC the full canonical
    encoding directly.
 3. Backward validation is sound only when validation and append share one stable log horizon.
    Commits must be serialized through a commit fence; lease epoch, write policy, retention floor,
    conflict validation, and append must be tied to the same logical decision. A check-then-append
    implementation with an interposing commit is false.
 4. Limited scans require a sealed certificate that distinguishes “stopped at the limit” from “exhausted
    the interval” and binds the ordered returned keys. The conflict window is the prefix through the
    last returned key in the first case, and the whole requested interval in the second.
 5. The requested read-plane non-interference theorem is true. A full-protocol simulator additionally
    needs the commit control transcript, because a conflict abort reveals one bit about whether an
    authorized observation window changed after the snapshot. No unauthorized payload is revealed,
    but the bit exists and must be named.
 6. Strict serializability holds for committed mutations in commit-timestamp order. Read-only invo-
    cations obtain a single, possibly stale, snapshot. A Byzantine cell may lie in its application-level
    return value; only the broker-served grant transcript is guaranteed to equal the snapshot.
 7. Variant B is recommended for v0.7. It has the same Byzantine authority boundary and the same
    T2/T3 theorem class as Variant A, while avoiding aborts on unused prewarm. Variant A is useful
    as an honest-client safety belt, not as a Byzantine completeness proof.
The result therefore matches the project’s risk register: the high-risk boundary is authority, not
arithmetic integrity. The executor may compute nonsense. It may not acquire database authority that
the broker did not grant.


1     Model
1.1   Trust, principals, and the meaning of statelessness
There is a trusted storage system, a trusted broker/committer role, and arbitrarily many probabilistic
polynomial-time Byzantine cells. Every process that possesses the capsule key is part of the trusted
computing base. Storage is assumed to implement the MVCC and lease contracts stated below; a
Byzantine database server is outside this model.
A cell context is

Here s is the fixed snapshot timestamp and e is the lease epoch placed in the cell’s context. All integer
fields are canonical unsigned 64-bit integers; the abstract timestamp and epoch spaces are therefore
restricted to [0, 264 − 1] in the encoded protocol.
[REPAIR C-CHANNEL] The request-supplied context is not authoritative. A broker handler
obtains an immutable expected context ctxc from trusted launch or channel metadata and verifies against
ctx. A serialized context in a request is either omitted or required to equal ctx.

condition under which binding the MAC to cid means “wrong-cell rejection” rather than merely “a
bearer object carrying someone else’s public cid.” It requires no evolving capsule state: a per-socket

“Stateless broker” means that the broker need not remember the latest capsule digest, a read list, or
a per-invocation sequence number. It may retain immutable connection/launch metadata and global
state such as policy, lease, log, and key material. Because the broker accepts any valid prior capsule,
the issuance structure for a Byzantine cell is a branching tree, not necessarily one monotone chain.
A coalition of cells may share arbitrary data out of band. The channel binding prevents one cell from
relabeling a request as another live context on its own channel; a cooperating holder of the other context
can of course exercise that other context’s authority. No protocol can stop principals from sharing data
they were each authorized to receive.

1.2   Reality ledger: current code and proved protocol
Implemented and tested today: the point-entry capsule seal and canonical encoding described in
Section 1; the grow-and-reseal read protocol over a Unix-domain socket; point and prefix reads against
the production-shaped Postgres schema, including tombstones; and an in-memory single-writer commit
function that performs backward OCC validation but is not wired to V8 or the broker. The running
prototype pins one broker-startup snapshot and its read gate is effectively “any key within the pinned
tenant/deployment”; the seal format already binds a snapshot per capsule. The current wire capsule
contains point entries only. A prefix result can populate point entries, but it does not yet carry the
sealed range certificate required for phantom-safe mutation validation.
Proposed and covered conditionally by this proof: per-invocation snapshot selection; context
and epoch obtained from trusted launch and storage-lease authority rather than cell assertion; per-range
read policy and commit-time write policy; sealed range certificates; and the end-to-end commit fence
that couples lease, retention, policy, conflict validation, and append. The theorem is a specification
for that repaired v0.7 protocol, not a claim that the present read-only code already implements it.
Constant-time tag comparison and production secret provisioning remain implementation obligations
rather than mathematical lemmas.

1.5   Capsules and canonical content
A capsule is
                              Cap = (tenant, deployment, s, docs, ranges),
where docs : K ⇀ vd is a finite map and ranges is a finite ordered sequence of range certificates. The
sequence permits repeated scans; its position is part of the canonical content. Every returned key in
every range certificate must occur in docs with the exact returned versioned value. A repeated point
read at the fixed snapshot must agree with any existing map entry.
The semantic observation set is
      Obs(Cap) = {Point(k, docs[k]) : k ∈ dom(docs)} ∪ {Range(j, ranges[j]) : j is a valid index}.
The point atoms intentionally include prewarmed documents and range-returned documents. This may
duplicate conflict coverage, but duplication is safe and makes Variant A faithful to “entire capsule
content.”
[REPAIR W-CANON] The wire decoder is a canonical decoder, not a permissive map deserializer. It
rejects duplicate map keys, duplicate fields, contradictory entries, invalid range certificates, nonminimal
integer forms, trailing bytes, and any byte string that is not exactly the canonical encoding of the
parsed value. A valid write set and a valid declared subset are likewise canonical finite maps/sets with
no duplicate key. This is necessary because “last duplicate wins” parsing would let attacker-controlled
bytes have two meanings across parsing and MAC recomputation.

Verification accepts only the exact algorithm identifier, an exact 32-byte tag, a canonical capsule,

The requested literal injectivity claim for the full MAC input is impossible: canonical capsule encod-
ings range over more than 2256 values, while d has only 2256 possible outputs, so distinct capsules
with one context must collide by the pigeonhole principle. The proof obligation must therefore be

[REPAIR K-PREHASH] The stated assumption that keyed BLAKE3 is a PRF does not by itself
authenticate the prehashed capsule. The proof additionally assumes collision resistance of unkeyed
BLAKE3. Without that assumption, a tag for one capsule can be reused for a different capsule with the
same unkeyed digest without forging the keyed MAC. The minimum no-code repair is to add collision
resistance to the assumptions ledger. The cleaner future protocol repair is a new seal version that
MACs the full framed canonical capsule bytes directly; that version needs only the keyed PRF/MAC
assumption.
The exact, fixed algorithm prefix is safe without a length prefix because the verifier accepts one
known constant and strips a known number of bytes before parsing the first length-prefixed field. If
future algorithms share a key, their top-level tags must be exactly dispatched and disjoint (preferably
length-framed or prefix-free). BLAKE3’s tree construction and the absence of Merkle–Damgård length
extension do not repair digest aliasing; this proof uses no length-extension argument.

1.7   Read issuance relation
For each context, Issued(ctx) is the least set satisfying:
 1. The trusted broker may issue an initial capsule at s. Every prewarmed point or range observation
    must pass the same read policy check that a trap would pass, and its choice must not encode data
    outside the context’s authorized leakage.
 2. Given any sealed capsule in Issued(ctx), the broker verifies it, checks P.read before storage access,
    evaluates the allowed point or scan at σs , merges the exact result, and issues a new seal over the
    full merged capsule.
[REPAIR P-PREWARM] Prewarming is an ideal read grant, not an exception to policy. Each
prewarmed item is policy-checked and included in the grant transcript. A learned prewarm selector
may depend on public context and prior authorized access patterns, but not encode another tenant’s
secret state into the choice of entries.
A transition is monotone relative to its input capsule. Global monotonicity is not enforced: a Byzantine
cell can replay an earlier capsule and obtain two branches. The broker stores no “latest” digest.

1.8   Commit protocol and the commit fence
A request contains the channel-bound context, a sealed capsule, a declared subset S when Variant B is
used, and a canonical write set W .

Variant B chooses an exact subset

[REPAIR B-SUBSET] A Variant B declaration references exact observation atoms: a point declaration
must match the sealed key and exact versioned result; a range declaration must identify an exact sealed

range-certificate entry, not a narrowed or rewritten interval. The verifier rejects duplicate declarations
and any atom not structurally present in the capsule.
The following abstract operation defines the required atomicity. It is implementable by one commit
mutex plus storage fencing in a single process, but the retention and lease parts must remain valid
across failover; in Postgres it naturally maps to a transaction/lock over lease and retention metadata
plus the commit log.
 CommitFence(ctx, Cap, R, W):
   enter a storage-visible commit/validation serialization fence
   require the committer’s epoch e_now was acquired and fenced at storage
   read log tip h only after that epoch-acquisition fence
   read monotonic wall/log time Now and retained low-watermark g
   require ctx.e == e_now
   require ctx.s <= h
   require ctx.s >= Now - Delta                 // product max-age rule
   require g <= ctx.s                           // actual coverage rule
   pin the retained interval so g cannot advance past ctx.s
   evaluate P.write(ctx, W) against policy version p
   require no committed write in (ctx.s, h] intersects any point/window in R
   atomically append W at fresh c > h iff:
       the storage lease still accepts ctx.e, and
       the policy decision/version p is still current
   release the fence and retention pin

[REPAIR A-ATOMIC] Conflict validation and append must share one stable horizon h. No successful
commit may interpose after validation and before this request’s append. On failover, the new epoch’s
storage acquisition/fence must complete before it reads h; every old-epoch append that succeeds is then
already in that prefix, and every later old-epoch append is rejected. A local precheck followed by an
unlocked append is unsound even with one nominal committer thread pool.
[REPAIR G-RETENTION] The age check alone is not race-free. The committer reads the actual
retained low-watermark g and holds a retention pin or a global commit/GC fence until append or abort.
GC may not delete an event in (s, h] while it is being validated.
[REPAIR P-WRITE] “Write policy at commit time wins” means the policy decision is linearized
with append. If policy can change independently, the append is conditional on the policy version used
by V5 or holds a policy read lock. A check that can be revoked before append is not commit-time
authorization.
The storage append itself performs the epoch check atomically. If failover races the request, either the
old-epoch append linearizes before the new epoch’s fence, or the append is rejected. Fresh timestamp
assignment is part of the append.

1.9    Retention notation
Let g be the greatest timestamp below which validation history is no longer guaranteed available, so
every write event in (g, h] is available while pinned. The exact safety condition is g ≤ s. The product
rule s ≥ Now − ∆ is a convenient hard age bound under a storage contract that retains the whole
interval newer than Now − ∆; it is not a substitute for reading and fencing the actual low-watermark.

Counterexample 2.1 (Why T1a cannot mean “latest”). Let Cap0 be the initial sealed capsule and
let the broker issue Cap1 ⊃ Cap0 after a read. The cell computes W from the additional value in Cap1
but submits the still-valid seal on Cap0 . V1 accepts. No MAC forgery or splice occurred. A stateless
verifier cannot distinguish this trace from an application that stopped at Cap0 and issued a blind write.
Preventing it requires stateful anti-rollback or a trusted observable-use mechanism, neither of which is
in the proposed protocol.
Counterexample 2.2 (Why keyed-PRF security alone is insufficient). Literal injectivity is impossible
for any 256-bit prehash over the unbounded set of finite capsules: collisions exist by counting. More
sharply, the assumptions as originally written permit a hypothetical world in which keyed BLAKE3 is a
secure PRF while the separately keyed-mode-independent unkeyed hash H maps every capsule encoding
to one constant. A tag obtained for one capsule would then verify for every other capsule with the same
context. This is not a claimed practical attack on BLAKE3; it is a proof-theoretic countermodel showing
that the desired theorem does not follow from the stated assumption. Collision resistance of H, or direct
MACing of the full encoding, closes the computational gap.
Counterexample 2.3 (Why T1b needs a control transcript). Consider two executions with the same
context and the same allowed point-read transcript at snapshot s, returning x = 0. In one execution no
later write touches x; in the other, another transaction writes x after s. Submitting the same declared
read and an authorized write succeeds in the first execution and aborts in the second. A simulator given
only the original grant transcript cannot determine which result to emit. The conflict bit is authorized
control leakage and must be included in the full ideal functionality.

2.5   Lemma R – retention safety
[REPAIR R-AGE] The exact safety predicate is retained conflict coverage g ≤ s. The age rule
s ≥ Now − ∆ remains mandatory as the product’s uniform admission rule under its stated retention
contract, but an implementation must also inspect and pin the actual low-watermark.

2.6   C1 – read-plane scale-out
Corollary 2.12 (C1: read-plane scale-out). Any trusted process holding κ, able to read the fixed MVCC
snapshot, and enforcing the same read policy may verify, grow, and reseal a capsule. It need not hold
the writer lease. Only the single committer executes the repaired commit fence and storage append.
Therefore read brokers may scale independently without changing T2, because the committer re-verifies
every capsule and validates its observations against the authoritative commit history. A read broker
with stale epoch information can at worst produce a capsule whose later commit aborts under V2.

2.7   Out-of-scope properties
No liveness is claimed against Byzantine cells: a cell may never submit, may request denial, may
replay stale capsules, or may intentionally force aborts. Denial-of-service, resource exhaustion, fairness,
scheduler attacks, timing/cache/speculation side channels, and compromise of a key-holding broker
are outside the theorem. Exactly-once request execution is also outside scope; a replayed request is
revalidated and may commit as another serial transaction.
For an honest cell in a quiescent system, obstruction freedom does hold under ordinary availability
conditions: if its snapshot remains retained, its epoch stays current, policy remains authorizing, and no
committed write intersects its declared observations, the commit fence finds no conflict and appends.


3     Proofs
3.1   Canonical encoding and outer-message injectivity
The proof uses a typed, canonical grammar. Byte strings are encoded as an eight-byte little-endian
length followed by exactly that many bytes. Fixed-width integers have one representation. Sum types
carry a fixed variant tag before the variant payload. Finite lists carry a length/count and preserve order.


                                                 13 of 27
The Capsule Transaction Theorem                                                                  Aster v0.7


Finite maps carry a length/count, keys in strict canonical order, and no duplicate keys. Documents
recursively use the same rules for field names and tagged values. The fixed capsule domain string occurs
at a grammar-known offset zero.
Lemma 3.1 (Canonical capsule encoding is injective). For every two well-formed capsules C, C ′ , if
E(C) = E(C ′ ) then C = C ′ .

Proof. Define a deterministic decoder by structural recursion on the capsule type.
At the root, the decoder first consumes the exact fixed domain string. This string need not be length-
prefixed because its length and expected bytes are constants in the grammar. It then decodes the
product fields in the one specified order.
For a length-prefixed byte string, the next eight bytes determine a unique unsigned length n, and the
decoder consumes exactly the next n bytes. Hence no bytes belonging to one string can be reallocated
to the next field. For a fixed-width integer, the next eight bytes determine exactly one integer. For an
option or enum, the variant tag determines both the variant and the grammar of the following payload.
For a list, the declared count determines the number of recursively decoded elements. For a map, the
declared count does the same, and strict key ordering plus duplicate rejection gives one mathematical
finite map rather than several wire descriptions of it. Recursive document values terminate because
every encoded value is finite and each recursive branch consumes a positive, bounded portion of the
input.
The range-certificate decoder additionally checks the structural invariants in Definition 1.1; thus a byte
string cannot decode both as an exhausted certificate and as a boundary certificate. After the last field,
canonical decoding requires end of input, so trailing bytes cannot be ignored.
It follows by induction on the type tree that decoding E(C) returns exactly C and consumes all bytes.
If E(C) = E(C ′ ), applying this deterministic decoder to the common byte string returns both C and
C ′ , hence C = C ′ .
Lemma 3.2 (Outer MAC framing is injective in context and digest). Let d, d′ be 32-byte strings and
let the accepted algorithm tag be the one fixed constant. If

                                         M (ctx, d) = M (ctx′ , d′ ),

then the cid, epoch, digest, tenant, deployment, and snapshot fields are pairwise equal.

Proof. Remove the common fixed algorithm prefix of known length. The next field is a length-prefixed
cid, so equality of the remaining byte strings gives equality of its length and bytes. The next eight bytes
give equal epochs. The next length-prefixed field gives equal digests; although the digest is already
fixed-size, framing makes the parse explicit. The next two length-prefixed fields give equal tenant and
deployment byte strings. The final eight bytes give equal snapshots, and end-of-input prevents a suffix
ambiguity. This is a direct left-to-right parse; no field boundary depends on the contents of a later
field.
Proposition 3.3 (The implemented outer message is not injective in the full capsule without hash
collision resistance). Distinct capsules with the same context can produce the same outer MAC input
exactly when their unkeyed digests collide.

Proof. For a fixed context, the only capsule-dependent component of M is d = H(E(C)). Therefore
M (ctx, C) = M (ctx, C ′ ) if and only if H(E(C)) = H(E(C ′ )). Lemma 3.1 ensures C ̸= C ′ implies
E(C) ̸= E(C ′ ), but injectivity of the encoding does not imply injectivity of a fixed-length hash. Collision
resistance is the computational condition excluding an efficiently found pair.

3.3   Proof of T1b
Proof of Theorem 2.7(a). Fix a coalition and an arbitrary adaptive strategy. The simulator receives
every public context and the ordered ideal grant transcript, including initial prewarm items, policy
denials, exact point/range answers, and public message lengths.
The simulator reconstructs every capsule state that an honest broker would produce along each branch.
It can do so because a capsule transition is a deterministic merge of the prior canonical capsule and the
next transcript answer. It computes the public unkeyed digest and outer message for each reconstructed
capsule.
To simulate tags, the simulator uses a lazy random function table T . On the first occurrence of an
outer message M , it samples a uniform 256-bit string and stores T [M ]; on repeats it returns the stored
value. For a submitted capsule/tag pair, it performs all public canonical/context checks and accepts
exactly the pairs present in its issuance table. It rejects other tags.
Replace the real keyed-BLAKE3 function by a truly random function. The distinguishing loss is the
PRF advantage. In the random-function hybrid, issued tags have exactly the simulator’s distribution.
The only remaining behavioral difference is that the real verifier might accept a nonissued pair. By the
T1a reduction, this occurs only with the MAC-forgery/hash-collision probability. All successful allowed
read responses are already in the ideal transcript; all denied requests are rejected before database access.
Therefore, excluding timing and other named side channels, no other database-dependent value reaches
the coalition.
Adaptivity causes no difficulty: the transcript and simulation proceed online, and the coalition’s next
request may be any function of its prior simulated view. For multiple colluding contexts the simulator
runs one shared random-function table, matching the real shared key, and gives the coalition the union
transcript. This proves computational indistinguishability and the payload non-interference claim.

Proof of Theorem 2.7(b). Counterexample 2.3 shows that the read-grant transcript alone is insufficient
once commits are visible. Give the simulator instead the ordered outputs of FAster : V1-style format
errors, epoch and retention outcomes, write-policy outcomes, conflict outcome, and successful commit
timestamp. The simulator handles capsule tags exactly as in part (a) and emits the supplied control
result for each ideal commit call.
By construction, the ideal commit function touches hidden database state only to evaluate conflict
predicates over exact declared authenticated windows and to apply an authorized write. Its output
contains no document value. Therefore a difference in an unauthorized key that does not alter an
allowed grant, public policy/epoch/retention metadata, or a declared authorized conflict window cannot
alter the ideal transcript. The real and ideal protocol encodings are indistinguishable by the same
PRF/T1a hybrid. This proves the repaired whole-protocol confinement statement.
Remark 3.5 (Meaning of “transitive closure”). The phrase means adaptive closure: after receiving one
allowed payload, a cell may compute the key or range for the next request, which may reveal another
allowed payload, and so on. It does not mean closure under arbitrary database relations the policy did
not authorize. A coalition’s closure is taken over the union of its contexts’ grants.

3.6    Atomicity of validation and append
Counterexample 3.9 (Unlocked validation is unsound). Let T1 and T2 share snapshot s with x = y = 0.
Let T1 read y = 0 and write x = 1, while T2 reads x = 0 and writes y = 1. If both validate concurrently
against the same tip h = s, both see no conflict and may append. In the order T1 ; T2 , T2 ’s read of x is
false; in the order T2 ; T1 , T1 ’s read of y is false. Hence no serial order realizes both reads. Serializing
each validation with its append makes whichever transaction validates second see the first writer in (s, h]
and abort.
Lemma 3.10 (Commit-fence horizon). For every successful commit T , there is a unique horizon hT
such that: (i) hT is the timestamp of the log tip immediately before T ; (ii) V4 covers (sT , hT ]; (iii)
no other successful commit lies between that validation and T ’s append; and (iv) cT > hT is the next
append in the total order.

Proof. The repaired commit fence serializes successful append decisions in storage-visible order. A
committer for a newly acquired epoch may not read h until its storage lease acquisition/fence has
completed. Hence every old-epoch append that succeeds is ordered before that acquisition and is already
present in the subsequently read prefix; every old-epoch attempt after the fence is rejected. While the
request then holds the commit/validation fence, no current-epoch append can interpose between its
validation and append. Thus every successful request observes a stable pre-append tip and immediately
appends after it in the global storage order.

3.7    Epoch fencing across failover
Lemma 3.11 (Epoch block order). Under the storage lease assumption, no commit carrying epoch e is
ordered after a successful commit carrying epoch e′ > e.

Proof. Let the storage-level acquisition/fence for e′ be the point after which append attempts from
epochs below e′ are rejected. A successful e′ append occurs at or after that fence. Any e append that
races the fence has two possibilities: it linearizes before the fence and therefore before every e′ append,
or it reaches the atomic epoch check after the fence and is rejected. There is no third possibility in
which it succeeds after an e′ append. Because timestamp assignment is part of the same atomic append,
the timestamp order agrees with this epoch order.

For a read-only invocation, trusted issuance evaluates every grant at the fixed σs , so the grant transcript
is a legal read-only transaction at that prefix. No backward validation is performed, so if s is stale
relative to a completed update, the query need not satisfy strict real-time freshness. Finally, a Byzantine
cell can transform or fabricate its outward application result; the theorem authenticates the broker’s
observations, not that output.

3.9   Proof of T3
Proof of Theorem 2.10. Fix one successful Byzantine-produced request and the complete finite read-
grant transcript that preceded it. By T1a, its accepted capsule C was actually issued for the request
context, except with negligible probability. Every successful grant in the real transcript arose from a
finite authorized issuance branch. Let the accepted write set be W .
Construct a client program AC as follows. Under the same external schedule, it reproduces the successful
grant requests and branch choices from the real transcript, thereby obtaining the same complete sequence
of grants. It retains every bearer capsule, including C, and finally submits the same canonical request.
Under Variant A it submits the earlier or latest selected capsule C and hence R = Obs(C); the stateless
protocol does not require that C be the most recently issued branch. Under Variant B it submits the
same exact subset S. The program contains all query choices and W as literal constants and therefore
need not causally depend on any omitted observation. All objects have polynomial size because they
occurred in a PPT execution, so this is a valid finite protocol client.
The program follows every protocol rule: it uses a broker-issued seal, declares only allowed exact subset
atoms, and requests only the write the original request submitted. Since the original request committed,
V5 proves that W was authorized at its append point. Replacing the Byzantine computation by AC

while retaining the same external schedule presents the committer with the identical bytes and therefore
the identical validation outcome and commit timestamp.
Rollback causes no problem for the existential witness. If the Byzantine cell had later or forked capsules,
AC may reproduce those same grants, retain them as unused, and still submit the accepted earlier
capsule because the repaired theorem intentionally preserves stateless bearer replay. Under Variant B,
prewarmed or actually observed but undeclared data is likewise treated as unused by the witness. This
establishes external-trace equivalence with the same complete grant transcript.
The policy consequence is immediate: T1b confines reads to grants, V5 confines writes to the policy
envelope, T1a prevents fabricated observations, and T2 orders all successful effects. What remains is
exactly the power to choose bad authorized writes and bad application outputs, which is the power of a
malicious or buggy application inside the same capability boundary.

3.10    Proof of C1 and obstruction-freedom remark
Proof of Corollary 2.12. Read issuance requires the key, trusted policy enforcement, and access to σs ;
it never appends. A read broker’s output is later checked by the committer under the same key and
context. T2 depends on trusted issuance plus authoritative commit-time validation, not on the read
broker holding the lease. Therefore adding trusted read brokers adds MAC-oracle capacity inside the
TCB but no new serialization point. Only the committer’s log horizon and append determine the serial
order.

For an honest request in a quiescent interval, every V4 predicate is false, so after the repaired epoch,
retention, and policy checks the append succeeds. A failover or retention expiry may force retry;
Byzantine actors can always deny liveness by load or self-abort, which remains out of scope.


4      Attack appendix: all thirteen enumerated obligations
The briefing calls these “twelve” obligations but numbers thirteen. This appendix discharges all thirteen.
Some attacks are rejected; rollback and under-declaration are instead absorbed into the repaired theorem
boundary because the stateless protocol intentionally permits them.

1. Capsule replay across snapshots
A tag for snapshot s includes le64(s) in the outer MAC input, while the canonical capsule header
also contains s. Replacing the commit context by s′ ̸= s changes the outer message and fails V1 by
Theorem 2.4; a mismatched capsule header is rejected before MAC acceptance. Submitting the old
capsule with its exact old context is ordinary bearer replay, not cross-snapshot mixing. It must still
pass the current epoch check, the hard age and low-watermark checks, and V4 over (s, h]. Thus an old
observation either remains conflict-free and is legal at the append point, or the request aborts.

2. Cross-cell transplant
On a channel labeled with cid b, the broker verifies with cid b, not a cid supplied by the payload. A
capsule sealed for cid a ̸= b therefore changes the framed MAC message and fails by T1a. Without
Repair C-CHANNEL, copying both the capsule and public context a would succeed, which is why
channel binding is a load-bearing requirement. A coalition may ask the actual holder of context a to
submit on its own channel; that is exercise of a’s authorized capability, and the coalition is already
allowed to share a’s authorized payloads.

3. Cross-epoch replay and a commit racing failover
Changing epoch e to e + 1 invalidates V1 because epoch is MAC-bound. Keeping e makes V2 fail once
the authoritative lease epoch is e + 1. For an in-flight race, the storage-level epoch check occurs inside
atomic append. Lemma 3.11 gives the exhaustive order: the e append linearizes before the new fence
and receives an earlier commit timestamp, or it is rejected. No e commit can appear after an e + 1
commit.

4. Capsule splicing, rollback, and fork
Splicing entries from two capsules into a union not itself resealed changes the canonical capsule and
requires a MAC forgery or unkeyed hash collision under T1a. Rollback is different: an earlier complete
capsule was genuinely issued and remains valid. Under Variant A, all observations in the selected
old capsule are validated, but later branch observations are absent. Under Variant B, the cell can
additionally select a subset. Counterexample 2.1 disproves any stronger actual-read-completeness claim.
T2 survives because it serializes the selected authenticated R; T3 survives because an authorized witness
client can stop at that capsule and issue W as a blind constant.

5. Phantoms, including the exhaustion gap
For a full limited result k1 , . . . , kℓ , the sealed window is every key in the requested interval through
kℓ . An insert such as k4′ between returned keys is a write in that window and V4 aborts. If only three
results are returned with limit seven, the certificate is marked exhausted and the window is the entire
interval; an insertion after the third result but before the range end is therefore also caught. Lemma 3.7
proves both cases and explains why writes beyond the terminal boundary of a full result cannot affect
the first ℓ keys.

6. Absence flips
A point observation of (None, None) or of a tombstone is an authenticated point atom on k. A
concurrent insert, delete, or update has k ∈ dom(Wi ) and makes Changed({k}; (s, h]) true. V4 aborts,
and Lemma 3.6 is exactly the contrapositive safety argument. Absence is not omitted merely because it
carries no document bytes.

7. Encoding ambiguity, fixed tags, and payload substitution
Lemma 3.1 proves that the typed length-prefixed canonical grammar has one decode. Lemma 3.2 proves
that the outer field sequence has one parse. The unlength-prefixed algorithm prefix is safe because it is
one exact constant at a fixed grammar position; future algorithms must use disjoint exact dispatch.
Distinct capsule encodings can still share the fixed-length unkeyed digest only by violating Repair
K-PREHASH’s collision-resistance assumption. Thus payload substitution is reduced to either a hash
collision or a new-message MAC forgery. Exact 32-byte tag enforcement removes truncation ambiguity.

8. Variant B under-declaration
A cell may choose S ⊊ Obs(C), including omission of a read that actually influenced its JavaScript.
This can avoid an abort and can violate an invariant the tenant expected its program to maintain. It
does not let the cell invent the reads that remain in S, write outside V5, or create a nonserial history
for the summarized transaction. The accepted operation is equivalent, under T3, to an authorized
application that ignored those grants and issued the same constant or blind write. The exact gain is
semantic dishonesty inside the authorized tenant boundary, not additional database authority.

9. Over-declaration and prewarm poisoning
Variant A validates every prewarmed or gratuitously granted observation in the selected capsule; Variant
B can declare any exact subset. A malicious cell can request many authorized reads and thereby
make its own later commit more likely to abort. It cannot make another transaction abort merely by
holding or declaring a read: V4 consults only committed writes, and an in-flight read set is invisible
to other transactions. A committed malicious write may conflict with another transaction only where
write policy gives overlapping authority. CPU, memory, and queue exhaustion from read floods are
denial-of-service and explicitly outside scope.

10. GC/retention race
V3’s age comparison followed by an unlocked log scan is insufficient: the sweeper could truncate an
event after the check and before validation. Repair G-RETENTION reads the actual low-watermark
and pins it, or serializes GC cutoff advancement with the commit fence. Lemma 2.11 proves sufficiency
and supplies the stale-read counterexample when coverage is absent. The append releases the pin only
after the validation result has been consumed.

11. Duplicate keys and contradictory entries
The attacker controls wire bytes, so relying on a language map type after permissive decoding is
unsafe. Repair W-CANON requires duplicate-detecting canonical decode and byte-for-byte canonical
re-encoding. A capsule with two entries for one key, a write set with both Put and Delete for one key,
or a declared set with contradictory versions is rejected before V1/V4. Maps are strictly ordered and
unique; range key lists are strictly ordered; exact range references cannot be edited.

12. Policy TOCTOU
A read grant is evaluated at read time. Revoking it later cannot erase data already delivered, so the
capsule remains authentic and T1b records the historical grant. Write policy is evaluated at the append
decision and wins. Repair P-WRITE prevents a revocation between V5 and append by tying append to
the policy version or lock. If write authority has been revoked, the transaction aborts even though its
old reads remain valid bearer data. T3’s witness uses the same historical read grants and the same
current write authorization.

13. Whole-capsule replay across invocations
There is no nonce or issue time beyond the existing context tuple.                If exactly the same
(cid, e, s, tenant, deployment) is reused, a capsule is replayable while epoch and retention permit. T2
and T3 need no nonce: every replay is revalidated against all commits since s, rechecked under current
write policy, and either aborts or becomes another legal serial authorized transaction. A nonce would
provide invocation identity, not stronger isolation. What is not provided is at-most-once execution;
an API that needs it should add a storage-recorded idempotency key, which is separate from capsule
freshness.

• Compare MACs in constant time. The current prototype’s ordinary inequality must be replaced

7    Prior-art position and exact delta
FoundationDB demonstrates the classical systems core used by T2: clients read at an MVCC version,
submit read/write key ranges, and resolvers compare read ranges against recently modified ranges; its
paper also notes that snapshot reads are omitted from conflict ranges [1]. Aster’s proven delta is not a
new OCC rule. It is that each declared read result and range window has broker-minted provenance,
so an untrusted executor cannot fabricate the resolver’s evidence. Completeness still depends on the
variant and the rollback boundary.
Hyperledger Fabric’s execute-order-validate design has endorsing peers execute chaincode, construct
versioned read sets and write sets, and sign endorsements; later validation checks those results rather
than re-executing at validation time [2]. Aster does not trust or re-execute the tenant computation.
Its trusted broker signs data flow at serve time, and the write is treated as adversary-chosen but
policy-gated.
Basil targets Byzantine transactional storage and Byzantine participants with a replicated protocol; its
design uses 5f + 1 replicas per shard and provides Byzantine serializability [3]. Aster instead assumes
one trusted broker/storage authority and makes the executor Byzantine. The costs and threat models
are therefore different: Aster is not a one-node replacement for Byzantine storage replication, but a
way to remove the executor from the database-authority TCB.
TransEdge focuses efficient consistent read-only transactions across untrusted edge nodes [4]. Fides/TF-
Commit focuses atomic commitment and audit over untrusted server infrastructure [5]. Aster’s axis is
orthogonal: trusted storage and broker, untrusted application executor, and authenticated serve-time
observations feeding ordinary single-writer OCC.
The paper-ready thesis sentence that survives the proof is:
     Aster makes every submitted OCC observation provenance-authentic without trusting or re-
     executing the application executor; strict serializability then follows from classical backward
     validation, while any omitted dependency is demoted to an authorized blind application
     write rather than a cross-authority isolation failure.

8     Open problems
8.1   Reactive subscriptions over capsules
A subscription needs invalidation without placing a resident write log or database credential in the
cell plane. The promising direction is a broker-side approximate matcher with one-sided error: false
positives trigger harmless re-execution, while false negatives would violate freshness and are forbidden.
The certificate language developed for range windows is a natural input to such a matcher, but retention,
compaction, and subscription handoff across epochs require separate proofs.

8.2   Learned prewarming (“dream capsules”)
Learned prewarming interacts directly with the A/B verdict. Variant A converts prediction error into
conflict amplification; Variant B permits unused grants to remain outside S. A production design should
keep grant content and declared-use metadata separate, policy-check every predicted item, prevent
the predictor from encoding cross-tenant secrets in its choices, and measure whether capsule size itself
becomes a side channel or denial-of-service vector.

8.3   Zero-knowledge compliance transcripts
A zero-knowledge layer could prove that a transaction used only capabilities, query forms, and write
destinations allowed by a compliance policy, without revealing the underlying documents. It should not
be marketed as proof of JavaScript correctness. The useful statement is capability/protocol compliance,
not arithmetic or business-logic integrity.

8.4   Actual-dependency completeness without trusting V8
The repaired theorem exposes a clean open problem: can a system preserve prewarm and stateless read
serving while proving that every value causally consumed by a Byzantine executor appears in R? A
conventional MAC cannot attest to use. Stateful one-time finalization, a trusted monitor around every
cache hit, hardware attestation, or a proof-carrying execution mechanism are possible directions, each
spending a resource the present design intentionally avoids.


9     Confidence report
What a cryptographer should check first. Verify the exact Rust canonical encoder/decoder against
Lemma 3.1; confirm duplicate rejection and exact algorithm/tag handling; and review the two-case T1a
reduction, especially the added unkeyed-BLAKE3 collision-resistance assumption. The implemented
prehash is the only reason the proof is not a pure MAC reduction. A v3 direct-MAC format would
simplify this joint.
What a database/concurrency reviewer should check first. Verify that the production commit
path has one stable validation horizon across concurrent requests and failover, that GC cannot race the
log scan, that policy revocation cannot race V5, and that every physical index mutation affecting a
logical scan appears in the conflict structure. Model-check the interleavings in Counterexample 3.9 and
the epoch race in Lemma 3.11.
Single weakest joint. The weakest joint is the storage-facing conflict projection: the proof assumes
that validation sees a complete, immutable (s, h] and that every mutation capable of changing a point
or limited-range answer is represented by a write inside the corresponding validation key/window.
A missing index-entry mutation, an off-by-one range endpoint, or a GC/interposition race defeats

T2 without breaking any cryptography. This is the part to implement and test as though it were a

Overall confidence. Conditional on the assumptions ledger and the repaired commit fence, confidence

the prewarm policy rule. The theorem is ready to guide v0.7, but the commit/GC/policy transaction
and range-index projection deserve independent model checking before deployment.


Concluding statement
The composition is safe at the authority boundary. A broker-issued observation cannot be forged; a
declared observation cannot be crossed by an unseen committed write; a stale epoch cannot append;
and an authorized write that survives those checks occupies one unambiguous place in the commit log.
The executor remains free to be wrong, malicious, forgetful, or dishonest about its own dependencies.
Those behaviors collapse to the behavior of an authorized bad application, not to possession of the
database credential.
That is the Capsule Transaction Theorem Aster can honestly implement.
